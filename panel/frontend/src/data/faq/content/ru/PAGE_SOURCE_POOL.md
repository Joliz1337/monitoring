# Исходящие адреса

У каждой пары «адрес ноды → адрес:порт назначения» всего 64 512 исходящих портов. Когда десятки тысяч клиентов идут на один популярный сайт, порты кончаются, и процессор ноды уходит в их перебор. Раздел раскладывает исходящий TCP по всем IPv4-адресам ноды: Xray помечает соединения 30 метками (101–130), а нода сама раскладывает метки по своим адресам и ставит правила маршрутизации в ядре — потолок портов растёт кратно числу адресов.

## Как настроить

1. Добавьте ноде адреса — карточка «Сеть / IP-адреса» на странице сервера. С одним адресом раскладывать нечего.
2. Включите тумблер на этой странице. Нода поставит правила и будет следить за ними сама; снятая галочка у адреса исключает его из раскладки.
3. В конфиг Xray (Remnawave → Config Profiles) вставьте 30 outbound'ов с метками и балансировщик. Готовый кусок с кнопкой копирования — раздел Exit-прокси, вкладка «Ноды», блок «Конфиг для Remnawave: пул исходящих адресов».

Конфиг один на весь парк: метки везде одинаковы, а какой метке какой адрес — решает каждая нода сама, по кругу (30 меток на 3 адреса — по 10 на каждый). На ноде с выключенным пулом или одним адресом метки ничего не меняют — трафик идёт как раньше.

## Пример конфига

```json
{
  "outbounds": [
    { "tag": "DIRECT", "protocol": "freedom" },
    { "tag": "BLOCK", "protocol": "blackhole" },
    {
      "tag": "pool-01",
      "protocol": "freedom",
      "settings": {},
      "streamSettings": { "sockopt": { "mark": 101 } }
    },
    {
      "tag": "pool-02",
      "protocol": "freedom",
      "settings": {},
      "streamSettings": { "sockopt": { "mark": 102 } }
    },
    … pool-03 … pool-29 по тому же образцу, метки 103–129 …
    {
      "tag": "pool-30",
      "protocol": "freedom",
      "settings": {},
      "streamSettings": { "sockopt": { "mark": 130 } }
    }
  ],
  "routing": {
    "balancers": [
      {
        "tag": "source-pool",
        "selector": ["pool-"],
        "strategy": { "type": "roundRobin" }
      }
    ],
    "rules": [
      { "type": "field", "protocol": ["bittorrent"], "outboundTag": "BLOCK" },
      { "type": "field", "ip": ["geoip:private"], "outboundTag": "BLOCK" },
      … правила exit-прокси и остальные ваши правила …
      { "type": "field", "network": "tcp", "balancerTag": "source-pool" }
    ]
  }
}
```

Что важно в примере:

- Первый outbound остаётся вашим дефолтным, pool-outbound'ы добавляются в конец списка. Если у прямого outbound задан `domainStrategy`, повторите его в `settings` каждого pool-outbound'а.
- `selector: ["pool-"]` подхватывает все теги с этим префиксом, `roundRobin` раздаёт соединения по очереди.
- Правило с `balancerTag` — строго последнее в `rules`: оно ловит весь оставшийся TCP, поэтому блокировки и правила exit-прокси должны стоять выше. UDP под правило не попадает и идёт как шло — метки на UDP не действуют, а потолок портов касается только TCP.

## Полезно знать

- Xray ставит метку только с правом NET_ADMIN, а правила маршрутизации нода ставит в сети хоста — поэтому remnanode должен работать с `network_mode: host` и `cap_add: NET_ADMIN`. Установщик панели разворачивает его именно так.
- Пул и Exit-прокси на одной ноде вместе не включаются: оба решают, с какого адреса нода выходит наружу. В общем конфиге Xray они уживаются — на ноде с exit-прокси метки просто ничего не делают.
- Статусы: «Работает» — правила на месте; «Расхождение» — часть меток пропала из ядра, нода вернёт их сама в течение минуты; «Ошибка» — причина в подсказке рядом, чаще всего на ноде включён exit-прокси. Нужна нода 10.29.0.
- Проверить на ноде: `ip rule` покажет правила fwmark для меток 101–130 (в hex 0x65–0x82), `ss -tn` — соединения с разными исходящими адресами.
