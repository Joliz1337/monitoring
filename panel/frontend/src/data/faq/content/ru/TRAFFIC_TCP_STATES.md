# TCP-состояния

Соединение проходит несколько состояний от установки до закрытия. По их количеству легко понять, что происходит с сервисом.

| Состояние | Значение |
|---|---|
| LISTEN | Порт открыт и ждёт подключений |
| ESTABLISHED | Активные соединения — основная рабочая масса |
| SYN_SENT | Сервер сам пытается куда-то подключиться и ждёт ответа |
| SYN_RECV | Пришёл запрос на подключение, рукопожатие не завершено |
| FIN_WAIT | Соединение закрывается по инициативе сервера |
| CLOSE_WAIT | Клиент закрыл соединение, приложение — ещё нет |
| TIME_WAIT | Соединение закрыто и «дозревает» пару минут перед освобождением порта |

## О чём говорят перекосы

- Растущий **CLOSE_WAIT**, который не спадает — приложение не закрывает сокеты; лечится только исправлением приложения или его перезапуском.
- Десятки тысяч **TIME_WAIT** — норма для нагруженного прокси: это следствие большого числа коротких соединений, а не утечка.
- Много **SYN_RECV** при скачке трафика — похоже на SYN-флуд; такие атаки отражает анти-DDoS.
- Много **SYN_SENT** — сервер не может достучаться наружу: недоступен апстрим или не резолвится DNS.
