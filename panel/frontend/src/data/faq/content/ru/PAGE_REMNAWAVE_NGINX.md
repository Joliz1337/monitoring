# Remnawave nginx

Управление nginx на Remnawave-нодах из панели. Профиль — шаблон конфига на весь флот; ноды с установкой обнаруживаются автоматически по пути из настроек (по умолчанию `/opt/remnawave`).

## Как это устроено

Профиль состоит из трёх частей: **опции** (схема реального IP, сертификаты, fallback), **правила** (локации) и **привязанные серверы** (у каждого свой домен). Панель рендерит конфиг, подставляет домен ноды вместо `{{DOMAIN}}` и отправляет; нода проверяет его через `nginx -t` и применяет с graceful reload.

- Правила живут между маркерами `LOCATIONS START/END`. Правки **вне** маркеров сохраняются при изменении правил; изменение опций пересобирает конфиг целиком и такие правки теряет.
- Строки с `# auto: node` (`worker_rlimit_nofile`, `worker_connections`, `ssl_session_cache`) каждая нода пересчитывает под свою RAM и лимиты. Уберёте маркер — останется ваше значение.
- Импортированный чужой конфиг без маркеров работает в raw-режиме: конструктор правил недоступен, пока не нажмёте «Вставить шаблон».

## Порты

| Порт | Кто приходит |
|---|---|
| **443** | Все клиенты — и напрямую, и через CDN. Опция CDN порт не меняет, только источник IP |
| **PP-порт** (8449) | Только HAProxy. Отдельный порт нужен потому, что nginx не смешивает PROXY-заголовок и обычные соединения на одном порту |
| **80** | Только редирект на HTTPS и ACME — появляется, если включён соответствующий тумблер |

## Правила

**gRPC → Xray** — локация для VPN-трафика:
- *serviceName* обязан совпадать с `grpcSettings.serviceName` инбаунда, иначе Xray не примет запрос;
- *порт* — локальный порт инбаунда (проверить: `ss -tlnp | grep 127.0.0.1`);
- заголовок с IP клиента всегда перезаписывается — подделать его нельзя.

**XHTTP → Xray** — локация для XHTTP-инбаунда:
- *путь* обязан совпадать с `xhttpSettings.path` инбаунда, *порт* — локальный порт инбаунда;
- одно правило обслуживает все режимы транспорта: `stream-one` и аплоад `stream-up` приходят с типом `application/grpc` и уходят через `grpc_pass` (полный дуплекс), `packet-up` и даунлоад-стримы — потоковым проксированием без буферизации через keepalive-пул к инбаунду;
- сканер или браузер на этом пути получает ответ заглушки, а не 404 от Xray — угадавший путь не отличит его от обычной страницы сайта; ошибки, которые Xray адресует своему клиенту (400, 409, 413), проходят как есть, чтобы клиент видел причину;
- в инбаунде `noGRPCHeader` должен оставаться `false` — без типа `application/grpc` режим `stream-one` уйдёт в ветку без дуплекса и не поднимется;
- профиль, созданный до появления этого типа правила, добавит keepalive-пул только после «Вставить шаблон»; в импортированном конфиге без шаблона для `packet-up` с данными в заголовке добавьте в `http` руками `large_client_header_buffers 8 32k;` — локацией это не закрыть.

**Проксирование** — обычная локация на сайт: путь и адрес назначения.

Нельзя: одинаковые имена или пути у правил; правило с путём `/`, если заполнен fallback — эта локация уже занята им.

## Опции

**Fallback** — куда уходит всё, что не попало в правила (сканеры, боты, заход браузером), и ошибки Xray: упавшее ядро отдаст клиенту сайт вместо 502. Пусто — nginx ответит 404.

**Трафик через CDN** — включать, если перед нодой Cloudflare или аналог. Заголовок с IP клиента принимается только от указанных диапазонов; `0.0.0.0/0` означает «доверять всем» — тогда любой подделает свой IP одним заголовком.

**PROXY protocol** — для нод за HAProxy. Задайте порт; IP HAProxy необязателен (пусто = принимать от всех), но тогда **обязательно** закройте порт файрволом, иначе кто угодно пришлёт поддельный заголовок.

**Редирект 80 → 443** — добавляет server-блок на 80 порту. Работает, только если порт открыт в файрволе.

**ACME (Let's Encrypt)** — добавляет локацию `/.well-known/acme-challenge/`, через которую Let's Encrypt проверяет владение доменом при выпуске и продлении сертификата (проверка HTTP-01). Нужен, если сертификат выпускается certbot'ом по HTTP. **Не нужен** для wildcard-сертификатов: они выпускаются через DNS-01, и проверка идёт через DNS-запись, а не через веб-сервер.

**Отклонять чужой SNI** — сервер перестанет отвечать сертификатом на подключения с чужим или пустым SNI, то есть на сканирование по голому IP. Включать, только если все клиенты ходят строго с доменом ноды.

**Wildcard-домен (один на все ноды)** — базовый домен без `*.`, например `example.com`. nginx на каждой ноде принимает и его, и любой поддомен (`server_name example.com *.example.com`), а `{{DOMAIN}}` в путях сертификатов становится этим доменом. Домен у нод при привязке не нужен — достаточно один раз указать базовый в профиле. Работает **только с wildcard-сертификатом** `*.example.com`: обычный сертификат на один поддомен nginx отдавал бы на все имена, и клиенты получали бы ошибку TLS. Сертификат должен уже лежать на каждой ноде — проще всего раскидать его через раздел Wildcard SSL, по умолчанию он кладёт файлы в `/etc/letsencrypt/live/example.com/`, ровно куда смотрят пути ниже.

**Пути сертификатов** — при wildcard-сертификате без wildcard-домена в профиле уберите отсюда `{{DOMAIN}}`: каталог называется по базовому домену (`/etc/letsencrypt/live/example.com/`), а не по поддомену ноды. Плейсхолдер оставляют, только когда у каждой ноды свой отдельный сертификат.

Сам сертификат должен уже лежать на ноде — перед применением она проверяет файлы на хосте и при их отсутствии вернёт понятную ошибку, а не сырой вывод `nginx -t`. Монтировать каталог сертификатов в контейнер вручную не нужно: если каталог (включая кастомные пути) ещё не примонтирован, нода сама добавит volume в `docker-compose.yml` установки и пересоздаст контейнер.

## Домен ноды

Указывается при привязке и подставляется вместо `{{DOMAIN}}` — в `server_name` и, если плейсхолдер там оставлен, в пути сертификатов. Пишите тот домен, которым клиенты реально подключаются к этой ноде. Если в опциях профиля задан wildcard-домен, поле не показывается — все ноды обслуживают его поддомены.

## Чтобы Xray видел реальный IP

Без этого в статистике, лимитах устройств и банах будет `127.0.0.1`:

- в инбаунде обязателен `"sockopt": { "trustedXForwardedFor": ["X-Forwarded-For"] }` в `streamSettings`, рядом с `grpcSettings`;
- инбаунд слушает `127.0.0.1` — TLS терминирует nginx;
- ядро Xray свежее: для gRPC опция корректна с v26.6.22;
- правьте шаблон **в панели Remnawave**, а не файл на ноде — иначе синхронизация Remnawave затрёт правку.

## Маскировка

- Ответ на посторонний трафик — точная копия ответа заглушки: панель не добавляет своих заголовков и пробрасывает `Server` от неё, поэтому сравнить сайт напрямую и через ноду по заголовкам нельзя.
- Заглушка недоступна — соединение обрывается (`444`) вместо страницы ошибки nginx: обычные сайты 502 не отдают, это выдало бы прокси.
- Выдать адрес заглушки может её собственный ответ: редирект `Location` на её настоящий домен, абсолютные ссылки, `Set-Cookie` или CSP с чужими доменами. Проверка: `curl -skI https://домен-ноды/` и сравнить с прямым запросом к заглушке.

## Применение и откат

- Транзакция на ноде: бэкап → запись → `nginx -t` → при ошибке откат → graceful reload. Битый конфиг не уронит работающий nginx.
- Профиль заменяет `nginx.conf` целиком. Установки из установщика монтируют его фрагментом — нода переведёт монтирование на полный конфиг и пересоздаст контейнер; маскировочный блок с unix-сокетом из старого фрагмента пропадёт, перенесите его в профиль, если он используется.
- Статусы: **synced** — применён, **pending** — в очереди (офлайн-нода доедет сама), **failed** — ошибка, текст в логе синхронизации.
