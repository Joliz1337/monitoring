# DNAT-маршрутизация

Проброс портов на ноде средствами ядра: входящий порт → IP:порт назначения. То же, что маршрутизация в HAProxy, но без userspace-прокси — пакеты переписывает netfilter, поэтому нагрузка на CPU минимальна, а UDP пробрасывается наравне с TCP.

Профиль — полный набор правил проброса на ноде. Нода применяет его атомарно, запоминает у себя и сама возвращает после перезагрузки или сброса файрвола. Панель сверяет контрольную сумму правил и показывает счётчики соединений и трафика по каждому правилу на странице сервера.

## Входящий порт, конец диапазона, порт назначения

Три поля описывают одно правило «что слушаем → куда шлём». Конец диапазона превращает входящий порт в отрезок портов, а порт назначения решает, что делать с номером порта на цели: `0` — оставить тот же, что пришёл, любое число — свести всё в этот порт.

| Входящий | Конец диапазона | Назначение | Результат |
|---|---|---|---|
| 443 | — | 10.0.0.2 : 8443 | `нода:443 → 10.0.0.2:8443` — один порт на другой |
| 443 | — | 10.0.0.2 : 0 | `нода:443 → 10.0.0.2:443` — тот же порт |
| 20000 | 30000 | 10.0.0.2 : 0 | `нода:20000–30000 → 10.0.0.2:20000–30000` — каждый порт на такой же порт цели (порт-хоппинг Hysteria, когда сервер слушает весь диапазон) |
| 20000 | 30000 | 10.0.0.2 : 443 | `нода:20000–30000 → 10.0.0.2:443` — все порты диапазона сводятся в один (порт-хоппинг, когда сервер слушает только 443) |

Несколько разных входов на одну цель — это несколько правил (или один диапазон). Диапазон в диапазон с другими номерами (`20000–30000 → 30000–40000`) сделать нельзя. Правила одного протокола не могут пересекаться по портам — сработало бы только первое, а показывались бы оба, поэтому панель такое не сохранит.

## Несколько IP назначения — балансировка

В поле «IP назначения» можно перечислить несколько адресов через запятую: `10.0.0.2, 10.0.0.3, 10.0.0.4`. Как они используются, задаёт поле «Распределение» (появляется, когда адресов больше одного):

| Режим | Кто распределяет | Как |
|---|---|---|
| **По серверам** (по умолчанию) | Панель | Каждая нода профиля получает один адрес по порядку привязки: №1 → первый IP, №2 → второй, дальше по кругу. Новый сервер встаёт в конец, у остальных адреса не меняются. Что кому досталось — видно во вкладке «Серверы» |
| **Случайно** | Нода | Каждая нода получает весь список и раскидывает новые соединения по адресам случайно и равномерно |
| **По кругу** | Нода | Строго по очереди: 1-е соединение → первый IP, 2-е → второй, … |
| **По IP клиента** | Нода | Адрес выбирается хэшем от IP клиента: один клиент всегда попадает на одну цель, пока список не менялся. Нужно протоколам, где от клиента идёт несколько соединений, которым важно оказаться на одном сервере. Требует модуль ядра `xt_HMARK` (в Ubuntu есть) |

Во всех режимах выбор делается на первом пакете соединения, дальше оно живёт на выбранном адресе до закрытия — на лету никого не перекидывает. Проверки живости целей у DNAT нет: упавший сервер продолжит получать свою долю новых соединений, пока вы не уберёте его из списка. На странице сервера счётчики режимов «случайно/по кругу/по IP клиента» показываются по каждому адресу отдельно. Режимы на стороне ноды требуют агента 10.24.0 и новее.

## MASQUERADE — подмена адреса источника

Клиент `1.2.3.4` подключается к `нода:443`. Нода всегда переписывает адрес назначения на цель; галочка MASQUERADE решает, что делать с адресом отправителя.

- **Включено (по умолчанию):** отправитель тоже переписывается на адрес ноды. Цель видит соединение *от ноды*, отвечает ноде, нода возвращает ответ клиенту. Работает всегда, на цели ничего настраивать не нужно. Минус — цель не знает настоящий IP клиента.
- **Выключено:** отправитель остаётся `1.2.3.4`. Цель видит настоящий IP клиента, но ответ отправит ему напрямую, своим обычным маршрутом — минуя ноду. Клиент получит пакет с чужого адреса и отбросит его: соединение не установится. Работает только когда цель маршрутизирует ответы **обратно через ноду** — например, она в приватной сети или туннеле, и нода для неё шлюз по умолчанию.

Выключайте только если такая обратная маршрутизация уже построена. Нужен реальный IP клиента без неё — это задача HAProxy с PROXY protocol, DNAT так не умеет.

## Полезно знать

- Порт API ноды (9100/tcp) пробросить нельзя. Правило на порт SSH подсвечивается предупреждением: после применения SSH к ноде уйдёт на цель.
- Галочка «Правило включено» — пауза без удаления: выключенное правило остаётся в профиле, но с нод снимается и трафик по нему не идёт; включили обратно — применилось снова.
- Отвязка сервера от профиля (и удаление профиля) снимает с ноды все DNAT-правила; офлайн-нода получит это, когда вернётся в сеть. Снять правила вручную можно и кнопкой на странице сервера.
- Права: домен `dnat` в NODE_CAPABILITIES ноды.
