# DNAT-маршрутизация

Проброс портов на ноде средствами ядра: входящий порт → IP:порт назначения. То же, что маршрутизация в HAProxy, но без userspace-прокси — пакеты переписывает netfilter, поэтому нагрузка на CPU минимальна, а UDP пробрасывается наравне с TCP.

## Как работает

Профиль — полный набор правил проброса на ноде. Нода применяет его атомарно в трёх собственных цепочках iptables (`nat/PREROUTING` DNAT, `nat/POSTROUTING` MASQUERADE, `filter/FORWARD` ACCEPT), запоминает у себя и сама возвращает после перезагрузки или сброса файрвола. Панель сверяет контрольную сумму правил, показывает счётчики соединений и трафика по каждому правилу на странице сервера.

| Поле | Значения |
|---|---|
| Протокол | TCP, UDP или оба |
| Входящий порт | Один порт или диапазон (конец диапазона) |
| Назначение | IPv4 и порт; порт 0 — сохранить входящий (диапазон уходит целиком) |
| MASQUERADE | Включено по умолчанию: цель отвечает ноде, а не клиенту. Выключайте только если цель маршрутизирует ответы через эту ноду |

## Полезно знать

- Порт API ноды (9100/tcp) пробросить нельзя, правила с пересекающимися портами одного протокола не сохраняются. Правило на порт SSH подсвечивается предупреждением.
- Цель видит соединения с адреса ноды (MASQUERADE) — реальный IP клиента до неё не доходит. Нужен реальный IP — используйте HAProxy с PROXY protocol.
- Отвязка сервера правила не снимает: снять их можно кнопкой на странице сервера.
- Права: домен `dnat` в NODE_CAPABILITIES ноды.
