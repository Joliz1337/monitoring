# GRE-туннели DDoS-Guard

DDoS-Guard («Защита сети») фильтрует трафик защищённого адреса и передаёт его на сервер по GRE-туннелю. Клиенты подключаются к адресу DDoS-Guard (CE), а настоящий IP сервера им не виден. Получается как релей, только без отдельного сервера и HAProxy.

## Как настроить

1. В кабинете DDoS-Guard откройте услугу → «Об услуге» → «Подключение» и скопируйте блок «Параметры подключения» целиком.
2. Здесь нажмите «Добавить туннель», вставьте текст в «Вставить со страницы DDoS-Guard» и нажмите «Заполнить». PE подставится сам — это второй адрес сети /30, обычно CE − 1.
3. Сохраните. Через минуту-две статус туннеля в кабинете DDoS-Guard сменится на «Активен», а здесь появится «Пакеты идут».
4. Клиентам давайте адрес CE: в Remnawave укажите его адресом хоста. Xray, который слушает `0.0.0.0`, принимает соединения на CE сам.

Статические маршруты из инструкции DDoS-Guard вручную ставить не нужно. Нода отправляет в туннель только трафик с адреса CE, основной маршрут сервера не трогает.

## Firewall

| Что разрешить | Зачем |
|---|---|
| Всё с адреса GRE DST (`185.129.101.255`) | Через него приходят GRE-пакеты. Без этого правила UFW пропускает туннель, только пока сервер сам что-то отправляет, и туннель пропадает после паузы или перезагрузки |
| ICMP из `198.18.100.0/24` | Сеть проверок DDoS-Guard. UFW по умолчанию пропускает пинг, правило нужно, только если ICMP закрыт |

Правило для GRE DST ставится в терминале сервера: `ufw allow from 185.129.101.255`. Профиль firewall панели такое правило задать не может (у правила обязателен порт) и при применении сбрасывает ручные правила. В белый список анти-DDoS оба адреса панель добавляет сама.

## Полезно знать

- «Пакеты идут» считается по входящим пакетам туннеля. DDoS-Guard регулярно пингует CE, поэтому пакеты идут и без клиентов. Если 5 минут не было ни одного, туннель у DDoS-Guard неактивен или хостер режет GRE. При включённом уведомлении придёт сообщение в Telegram.
- «Проверить» пингует PE с адреса CE и делает запрос наружу с CE. Снаружи сервер должен быть виден как CE.
- GRE SRC должен стоять на сетевой карте. Если сервер за NAT облака и публичного адреса на интерфейсах нет, GRE через такой NAT обычно не проходит.
- Переходите со скрипта `ddg-tunnel.sh` — сначала отключите туннель в нём (пункт 4 меню). Ядро не поднимет второй туннель с теми же GRE SRC и DST, панель покажет «Конфликт».
- DNAT-правила и опубликованные порты Docker в режиме bridge на адресе CE не работают: ядро выбирает маршрут ответа до обратной подмены адреса. HAProxy и Xray в сети хоста работают.
- Нужна нода 10.35.0. Проверить на сервере: `ip -d link show gre-ddg1`, `ip rule` (правила 1150 и 1151), `systemctl status mon-gre`.
