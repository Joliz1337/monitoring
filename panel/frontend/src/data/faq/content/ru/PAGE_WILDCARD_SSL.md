# Wildcard SSL

Сертификаты вида `*.example.com` для флота: панель выпускает их, продлевает и сама раскладывает по нодам. Сертификатов может быть несколько — на разные домены.

## Как работает

1. Панель выпускает сертификат через Let's Encrypt, подтверждая владение доменом записью в DNS Cloudflare — открытые порты на серверах для этого не нужны.
2. Каждая нода с включённой доставкой получает выбранные для неё сертификаты.
3. Нода проверяет файлы, сохраняет копию текущих, записывает новые и перезапускает указанную службу.
4. Раз в сутки панель проверяет срок и продлевает сертификат заранее.

## Настройка ноды

Для каждой ноды выбирается, какие сертификаты ей нужны — один или сразу несколько, каждый ляжет в свою папку по имени домена. Там же указывается, куда класть файлы и какой командой перечитать сертификаты — например, перезагрузка nginx или HAProxy; команда выполняется один раз, после всех файлов. Можно задать нестандартные имена файлов или полные пути, если служба ожидает их в конкретном месте; с полными путями у ноды может быть только один сертификат.

Новый сертификат сам ни на какие ноды не попадает: отметьте его в карточках нужных нод или выберите для нескольких сразу массовым редактированием.

## Полезно знать

- Нужен API-токен Cloudflare с правом менять DNS-записи доменов. Домены должны обслуживаться в Cloudflare, токен — иметь доступ ко всем их зонам.
- Wildcard покрывает только один уровень: `*.example.com` подходит для `node1.example.com`, но не для `a.b.example.com`.
- Каталог сертификата называется по базовому домену, а не по поддомену — это важно, когда путь к сертификату прописывается в конфигах вручную.
- Если продление или доставка на часть нод не удались, панель пришлёт уведомление в Telegram с перечнем проблемных серверов.
- Это не то же, что сертификаты на странице HAProxy: там обычные сертификаты для одного сервера, выпускаемые по HTTP-проверке.
