# Эфемерные порты

Когда сервер сам куда-то подключается, ядро выдаёт соединению свободный номер порта из настроенного диапазона. Запас этих номеров не общий на сервер: он считается отдельно на каждую пару «наш адрес → адрес и порт получателя». На одно такое направление с одного адреса больше соединений, чем номеров в диапазоне, открыть нельзя.

Поэтому здесь показано два уровня. Полоса у адреса — его самое загруженное направление, то есть насколько близко этот адрес подошёл к потолку. Внутри раскрываются сами направления с занятыми номерами.

## Что делать при заполнении

- **Добавить адрес.** Запас умножается на число исходящих IP. Раздел «Исходящие адреса» раскладывает соединения по всем адресам сервера автоматически.
- **Развести по портам получателя.** Соединения на порты 443 и 8443 одного и того же сервера считаются раздельно — у каждого свой запас.
- **Проверить Time Wait.** Закрытые соединения держат номер ещё пару минут. При `tcp_tw_reuse = 1` в системных оптимизациях ядро отдаёт такие номера новым исходящим сразу, и в занятое они не попадают.

Заполнение выше 85% опасно не только отказами: подбирая свободный номер, ядро перебирает почти весь диапазон, и процессор уходит в системное время при том же трафике.
