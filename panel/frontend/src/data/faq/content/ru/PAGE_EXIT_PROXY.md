# Exit-прокси

На включённых нодах агент поднимает локальный SOCKS5 (127.0.0.1:порт), который вы указываете в Remnawave как outbound для Google-трафика. Нода сама следит за своими IPv4-адресами (основным и добавленными через панель) и за WARP, проверяет, как Google видит каждый выход, и выпускает трафик только через здоровый. Панель показывает состояние, хранит настройки и присылает уведомления — без неё прокси продолжает работать.

## Как выбирается выход

| Проверка | Что считается блокировкой |
|---|---|
| Страна по Google | Google относит IP к стране из чёрного списка (по умолчанию RU) — Gemini для такого адреса недоступен |
| Капча в поиске | Поиск отвечает страницей «подозрительный трафик» вместо результатов |
| Gemini | Страница Gemini сообщает, что сервис недоступен в вашем регионе |
| Свои проверки | URL отвечает запрещённым кодом, редиректом или текстом из шаблона |

Выбор липкий: текущий выход остаётся, пока проходит проверки, и меняется только когда «заболел» — тогда нода берёт первый здоровый по вашему приоритету и обрывает соединения старого выхода, чтобы весь трафик сразу шёл через новый. Если здоровых нет, используется первый по приоритету, а панель шлёт уведомление.

## Полезно знать

- Порт один на всех нодах, поэтому кусок конфига для Remnawave общий — он в блоке под списком нод. Весь Google ведите одним правилом, иначе Google увидит одну сессию с разных IP.
- Одиночный сбой проверки (таймаут) выход не переключает — только подтверждённая блокировка.
- Сквозная проверка идёт через сам socks и показывает, с какого IP реально выходит трафик.
- Прокси рассчитан на Gemini, поиск и API — YouTube и видео в этот outbound не отправляйте.
