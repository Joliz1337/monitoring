# Сеть / IP-адреса

Хостер выдал ноде ещё один адрес или блок адресов — здесь они вешаются на интерфейс без захода по SSH. Нода сама пишет их в свой сетевой конфиг (netplan, systemd-networkd, NetworkManager или `/etc/network/interfaces`), поэтому адреса переживают перезагрузку. Основной адрес и адреса, настроенные хостером, панель не трогает: удалить можно только то, что добавили через неё.

## Форматы ввода

| Запись | Что получится |
|--------|---------------|
| `203.0.113.10` | один адрес с маской /32 (для IPv6 — /128) |
| `203.0.113.10/24` | один адрес с указанной маской |
| `203.0.113.10-203.0.113.15` | по адресу на каждый номер диапазона (можно `…10-15`) |
| `203.0.113.32/29` | все адреса подсети целиком (сеть и broadcast пропускаются) |
| `2001:db8::2/64` | один адрес IPv6; подсети IPv6 не разворачиваются |

Не больше 256 адресов за одно применение. Адреса, которые уже стоят на интерфейсе, пропускаются.

## Как проходит применение

1. Нода делает бэкап конфига, записывает адреса, применяет их и запускает таймер отката на 120 секунд.
2. Панель заново подключается к ноде и подтверждает изменение — это и есть проверка, что связь не пропала.
3. Нет подтверждения к сроку — нода сама возвращает всё из бэкапа. Если сервер перезагрузился посреди операции, незавершённая транзакция откатывается ещё до старта сети.

Пока идёт ожидание, кнопка «Отменить» откатывает изменение вручную. После подтверждения панель пробует подключиться к каждому новому адресу на порт ноды — это справочно: у некоторых хостеров маршрутизация нового адреса подтягивается не сразу.
